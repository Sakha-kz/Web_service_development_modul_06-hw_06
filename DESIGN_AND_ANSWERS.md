# Отчёт и результаты тестирования: Модуль 06 (Домашнее задание)

## 📌 Архитектурные решения

1. **Защита эндпоинтов каталога товаров:**
   - Публичные эндпоинты `GET /api/products` и `GET /api/products/{id}` доступны для просмотра каталога анонимным пользователям без необходимости аутентификации (`[AllowAnonymous]`).
   - Операции добавления (`POST /api/products`) и удаления (`DELETE /api/products/{id}`) закрыты атрибутом `[Authorize]`.
2. **Внедрение и чтение Claims:**
   - При успешном прохождении логина в методе `AuthController.Login` формируется список утверждений (`Claims`), включающий `ClaimTypes.Name = request.Username`.
   - Внутри защищенного метода `POST /api/products` значение данного утверждения считывается из контекста запроса через `HttpContext.User.Claims` и сохраняется в свойстве сущности `AddedBy`.
3. **Безопасность секретного ключа:**
   - Секретный ключ подписи хранится исключительно на стороне сервера в конфигурационном файле `appsettings.json`.
   - Клиент получает только подписанную строку токена и ни в каком сценарии не имеет доступа к симметричному ключу сервера.

---

## 📊 Матрица проверки сценариев безопасности

| № | Сценарий проверки | Заголовок Authorization | Ожидаемый HTTP-код | Фактический результат |
| :-: | :--- | :--- | :-: | :--- |
| **1** | Запрос к `POST /api/products` без токена | *Отсутствует* | **401 Unauthorized** | Запрос прерван middleware безопасности |
| **2** | Получение токена через `POST /api/auth/login` | *Не требуется* | **200 OK** | Сервер вернул подписанный JWT-токен |
| **3** | Добавление товара с валидным JWT | `Bearer <valid_token>` | **201 Created** | Товар создан, поле `AddedBy: "student"` |
| **4** | Удаление товара с валидным JWT | `Bearer <valid_token>` | **200 OK** | Товар удален, зафиксировано имя оператора |
| **5** | Запрос с некорректным или модифицированным JWT | `Bearer invalid.jwt.payload` | **401 Unauthorized** | Не совпадает цифровая подпись HMAC-SHA256 |
| **6** | Запрос с истёкшим по времени JWT | `Bearer <expired_token>` | **401 Unauthorized** | Срок действия токена истек (`ValidateLifetime = true`) |

## 🔐 Важность разделения секретного ключа и токена

В соответствии с методическими требованиями:
* Секретный ключ (`SecretKey`) используется сервером для генерации цифровой подписи (хеширования заголовка и полезной нагрузки) и проверки неизменности токена при каждом входящем запросе.
* Клиент передает серверу исключительно результат — строку JWT-токена в заголовке `Authorization: Bearer <token>`.
* Передача самого секретного ключа клиенту нарушила бы принцип симметричной криптографии и позволила бы злоумышленнику выписывать произвольные токены с любыми ролями и правами доступа.
